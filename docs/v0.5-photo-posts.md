# Photo posts — Android 0.5.0 / iOS 0.2.0

## Use

1. Install the Android 0.5.0 ARM64 preview over the existing SnapTok installation. Do not uninstall: the signing identity is unchanged and Room migrates existing records to schema 4.
2. Open Settings → Photo posts. Choose Images, Slideshow or Both. Images is the default.
3. For slideshows, choose 2–10 seconds per image and whether to include music. The soundtrack repeats to fit the duration. Images fit the frame without cropping.
4. Share a public TikTok photo post to SnapTok, use Floating Save on Android, or paste it into Save. Manual input can override the remembered photo defaults.
5. Open the completed album to browse or share images. Both also provides Play slideshow. Android saves to Pictures/SnapTok and Movies/SnapTok, or the selected custom folder. iOS saves privately until explicitly exported to Photos or Files.

## Behaviour and boundaries

- Original image files retain source bytes and ordering. Gallery apps control their own display sorting. The in-app album preserves the post order.
- Photo support targets public TikTok `/photo/` posts and official short links resolving to them. Instagram carousels, private/login-only posts, live streams and every possible video-route alias are not covered by this change.
- Android resolves photo metadata and renders slideshows on device. iOS requires its configured private bridge for social media extraction and slideshow preparation. The bridge must remain reachable.
- Images-only requests do not require music. If music is requested for a slideshow but cannot be obtained or retained, the request fails with guidance; use Retry with current defaults/settings after turning music off. Audio-only mode is for video posts.
- Album downloads have bounded image counts, input/output sizes and processing times. Images are validated before publication; Saved means all requested outputs were published. Different output formats are distinct requests. Queued jobs retain their options.
- Rendering uses the first image's aspect ratio, letterboxes mixed shapes and does not upscale. Android uses Media3; the bridge uses FFmpeg. This is a slideshow with configurable timing, not a recreation of TikTok's interactive timing or effects.
- The iOS package importer accepts only a flat manifest of supported media, validates CRC and streamed extraction limits, checks images and playable video, and rejects unsafe paths and malformed packages.

## Reproduce

Android local checks:

```sh
scripts/build-local.sh --no-parallel --max-workers=2 :app:testDebugUnitTest :app:lintPreview :app:assemblePreview
```

With an isolated Android emulator, install the Debug and AndroidTest APKs, then run `PhotoPipelineTest` and `PhotoPublicationTest` through AndroidJUnitRunner with `-e photoUrl https://vt.tiktok.com/ZSbQFueH8/`. The publication test intentionally keeps the sample's saved media in that test device for visual inspection.

iOS and bridge checks:

```sh
ios/Scripts/check.sh
```

For the opt-in live roundtrip, run SnapTokCheck with `SNAPTOK_CHECK_BRIDGE`, `SNAPTOK_CHECK_TOKEN_FILE`, `SNAPTOK_CHECK_PHOTO_OUTPUT=both` and `SNAPTOK_CHECK_PHOTO_COUNT=10`, passing the sample URL. Do not print or package the connection token. `ios/Scripts/check-photo-post.py` separately validates bridge extraction/rendering into a new temporary fixture directory.
