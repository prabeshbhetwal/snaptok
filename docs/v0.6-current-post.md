# Android 0.6.0 — Save current TikTok post

## Setup on the S24 Ultra

1. Install the 0.6.0 ARM64 preview over the existing app. Keep the existing installation and data.
2. Open SnapTok Settings → Floating Save button. Enable the floating button and grant Appear on top if needed.
3. Enable Save current post · TikTok, read the disclosure and choose Agree and open settings.
4. In Android Accessibility → Installed apps, enable SnapTok — Save current post. Samsung labels can vary. If Android restricts the setting for this sideloaded preview, review SnapTok's App info and the permission before enabling it; copied-link mode remains available without Accessibility.
5. Open a video or photo post in English TikTok and tap the floating button once. Keep that post on screen until capture finishes. Share may appear briefly; downloading continues through the existing queue.

## Scope

This is an opt-in experimental Android adapter. The supported package names are `com.zhiliaoapp.musically` and `com.ss.android.ugc.trill`. The first adapter recognises exact English Share/Share video/Share post/Share photo/Share photos and Copy link controls. It does not rely on guessed screen coordinates or use an AI agent to choose actions. TikTok Lite, other languages, other social apps and arbitrary screen layouts are not claimed to work.

The sequence searches visible, enabled controls after an explicit floating-button tap, opens Share once, activates Copy link once, briefly takes focus for Android clipboard access and enqueues only a fresh valid TikTok post link. When a panel remains open, Back is used only if that panel was opened by this capture and Copy link is still recognisable. The post need not be copied manually when this adapter works with the installed TikTok version.

Capture is bounded by time and tree size. Ambiguous controls, app switching, locked screens, permission revocation, stale clipboard values and expired handoffs stop safely. There is no automatic fallback to downloading the previous clipboard link. A short failure message directs the user to Share → SnapTok. Duplicate handling, photo output, quality, folders, completion alerts and download retries remain owned by the existing queue.

## Privacy and controls

- Disabled by default. Consent is separate from Android's system permission.
- Accessibility event contents are not stored, logged or transmitted. The screen tree is inspected only during a requested capture and only for the supported TikTok package. No screenshots or gesture injection are requested.
- Clipboard access is limited to the foreground handoff. The automatically captured clipboard value must have an Android timestamp at or after the Copy link action and contain one valid TikTok post. URI clipboard payloads are not dereferenced.
- Turn Save current post off to restore the original copied-link behaviour. Revoke the service through Android Accessibility settings if it is no longer wanted. Hiding the floating button cancels any capture still in progress; downloads already queued continue.
- The service is declared `isAccessibilityTool=false`: this general downloader does not claim to be a disability-focused tool. A public Play release requires the applicable Accessibility declaration, prominent disclosure and policy review; no store approval is claimed.
