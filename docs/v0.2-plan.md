# SnapTok 0.2: download controls and feedback

Implement the user's requested additions while preserving instant sharing and existing download history.

- Make each original post URL an accessible link opening its source app/browser.
- Add explicit clipboard paste and clear manual input after durable enqueue succeeds; retain invalid input.
- Inspect a manually entered link on demand and list actual downloadable MP4 resolutions. Shared links use a saved default quality preference; no extra share-screen prompt. Best available remains the default. A preferred resolution (the shorter edge) selects the best available version at or below it, falling back to the lowest available if necessary.
- Select a persistent destination using Android's folder picker. Keep Movies/SnapTok as the default gallery destination. Snapshot destination and quality on each queued request, so changing settings does not redirect existing jobs. Retrying retains that request's original options.
- Migrate Room v1 to v2 without losing history. Deduplicate identical URL/quality/destination requests, allowing another quality or destination for the same source.
- Keep percentage progress visible in notifications; distinguish transfer from final file saving. Add completed and failed outcome notifications and brief outcome messages, with user controls. Android's required foreground-service indicator is retained even when optional notifications are disabled. In-app status messages remain available.
- Explain the on-device yt-dlp pipeline. Accept public X/Twitter video links as well as TikTok; no private-account/login support.

Validation: unit tests for quality selection, option snapshots, notification preferences and migration; Android tests for custom-folder publication and notifications; emulator checks for clipboard, link opening, quality menu and durable upgrade. Build a same-signature v0.2 APK and retain the v0.1 outputs.
