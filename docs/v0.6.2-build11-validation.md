## Upgrade-safety correction

Build 10 cleared original receipts only for newly created exports. Existing export records could still retain original-file `outputsJson` even though `mediaUri` pointed at the actual exported copy. Sharing/deleting those records therefore targeted the original. The focused `legacyExportsResolveOnlyTheirOwnFile` regression reproduced this failure before correction.

Shared `DownloadJob.outputs()` now recognises existing `export:` request keys and resolves only the export's primary `mediaUri`. Missing primary media produces no outputs; it never falls back to an original. This protects older video/audio records without rewriting the database or adding a migration. Ordinary album JSON remains authoritative. Newly created exports also retain the corrected independent receipts from build 10.
